# ADR 0001 · รากฐานแพลตฟอร์ม

สถานะ: ใช้งาน · 2026-11-21

## บริบท

- ร้านเช่ารถบนเกาะเต่าเป็นต้นแบบและลูกค้ารายแรก
- เป้าหมายระยะยาวมี 3 ข้อ
  1. ขายระบบบริหารร้านแบบ subscription (SaaS) ให้ร้านเช่าอื่น
  2. สร้าง Marketplace แยกเป็นอีก project
  3. ร้านเลือกเปิดของของตัวเองขึ้น Marketplace ได้
- ต้องวางรากฐานให้รองรับหลายร้าน หลายเครื่อง และ load balancer ตั้งแต่แรก โดยยังไม่จ่ายค่าโครงสร้างใหญ่ก่อนถึงเวลา

## การตัดสินใจ

| เรื่อง | ทางที่เลือก | เหตุผล |
|---|---|---|
| โครง repo | pnpm monorepo: `apps/api` (NestJS), `apps/web` (Next.js PWA, ยังไม่สร้าง), `packages/db` (Drizzle + SQL), `packages/core` (กฎธุรกิจล้วน) | แยกหน้าที่ชัด · กฎราคาและของว่างใช้ร่วมกันได้ทั้ง API, เว็บ (โหมดออฟไลน์) และ Marketplace |
| แยกข้อมูลร้าน | ฐานข้อมูลเดียว ทุกตารางมี `org_id` + Postgres RLS | ราคาถูกที่สุดต่อร้าน · RLS กันข้อมูลรั่วข้ามร้าน แม้โค้ด API ผิด |
| สิทธิ์ฐานข้อมูล | API ใช้ role `rental_app` ที่ไม่ใช่เจ้าของตาราง · งานก่อนรู้ตัวตนผ่านฟังก์ชัน `auth.*` (SECURITY DEFINER) | API ข้าม RLS ไม่ได้ · ฟังก์ชันคืนเฉพาะคอลัมน์ที่จำเป็น |
| ตัวตน | ผู้ใช้ระดับแพลตฟอร์ม เป็นสมาชิกได้หลายร้าน · username/เบอร์ไม่ซ้ำทั้งระบบ | คนเดียวทำงานหลายร้าน/หลายสาขาได้ · หน้าเข้าระบบไม่ต้องถามชื่อร้าน |
| session | token ทึบใน cookie httpOnly · ตรวจกับฐานข้อมูลทุกคำขอ (ไม่ใช้ JWT) | ตัดสิทธิ์เครื่อง/ปิดบัญชีแล้วมีผลทันที |
| เครื่องที่อนุญาต | cookie เครื่อง (สุ่ม, เก็บ hash) · เครื่องใหม่ต้องให้เจ้าของพิมพ์รหัส 4 ตัวอนุมัติ | ตรงกับ mock 1.W0 · เจ้าของอนุมัติเครื่องตัวเองได้แต่ถูกบันทึกเป็นรายการเสี่ยง |
| ประวัติการใช้งาน | `audit_log` เขียนในธุรกรรมเดียวกับการเปลี่ยนแปลง · แก้/ลบไม่ได้ (ไม่มีสิทธิ์ + trigger) | ตรงกับ mock 2.04 · ไม่มีใครลบได้รวมถึงเจ้าของ |
| เงิน | จำนวนเต็มหน่วยย่อย (สตางค์) · สกุลเงินผูกกับร้าน | ไม่มีทศนิยมเพี้ยน · รองรับหลายสกุลเงิน |
| id | `uuidv7()` ของ Postgres 18 | เรียงตามเวลา · เครื่องลูกข่ายสร้างเองได้ตอนออฟไลน์โดยไม่ชนกัน |
| เหตุการณ์ออกนอกระบบ | ตาราง `outbox_events` เขียนในธุรกรรมเดียวกัน | Marketplace, WhatsApp และ webhook ได้ข้อมูลครบ ไม่หาย ไม่ส่งก่อนบันทึกสำเร็จ |
| ไม่มี state ในเครื่อง | session อยู่ใน Postgres · rate limit / ตั๋วรออนุมัติเครื่องอยู่ใน Valkey · ไฟล์จะอยู่บน S3/R2 | รัน API กี่ตัวก็ได้หลัง load balancer |

## ขั้นของ infra

1. **ตอนนี้:** VPS 1 เครื่อง
   - Caddy ทำทั้ง HTTPS และ load balancer → API 2 ตัวขึ้นไป
   - Postgres, Valkey อยู่เครื่องเดียวกัน
   - ไฟล์ดู `infra/prod`
2. **ลูกค้า SaaS กลุ่มแรก:**
   - Postgres และ Valkey ย้ายไปบริการแยก แค่เปลี่ยน URL ใน env
   - API หลายเครื่อง
3. **Marketplace:**
   - ใช้ container orchestration
   - เพิ่ม read replica
   - Marketplace ใช้ฐานข้อมูลของตัวเอง แล้วรับข้อมูลจาก outbox

## สิ่งที่ยังไม่ทำ (ตั้งใจ)

- Kubernetes
- หลาย region
- แยก microservice
- ทำเมื่อมีตัวเลขการใช้งานจริงบอกว่าจำเป็น

## ผลที่ตามมา

- ตารางใหม่ทุกตารางต้องทำ 3 อย่าง
  - มี `org_id`
  - เปิด RLS พร้อม policy
  - มีเทสต์ใน `packages/db/test` ยืนยันว่าข้ามร้านไม่ได้
- คำสั่ง SQL ฝั่ง API ต้องเลือกคอลัมน์ของ `users` เอง เพราะ `password_hash` ไม่ได้ให้สิทธิ์อ่าน
